## Rollback paths, cheapest first

### 1. Whole v2 skin (visual only) — one constant

```
node scripts/sportsbook-v2-rollout.cjs 0 --push
```

Sets `ROLLOUT_PERCENT = 0` and pushes. Every visitor gets the classic
sportsbook on their next load (~80 s for GitHub Pages to serve the new asset).
No other file changes. Rolling forward again is the same command with `10`,
`50` or `100`.

### 2. Multi-pick slip (visual + entry model) - one constant

```
node scripts/sportsbook-multislip-rollout.cjs 0 --push
```

Returns every browser to the single-pick ticket. The multi-pick slip submits
each selection separately through the same `/api/picks` path, so nothing about
grading or records changes either way. Staged 10 -> 50 -> 100 on 2026-09-03
with health cycles at each step.

### 3. Idempotency client change — revert one commit

```
git revert 59fab27      # Sportsbook: send a submission identity with every Lock
```

`59fab27` (2026-09-03) is FRONTEND ONLY: it adds `submission_batch_id` and
`submission_item_key` to the Lock payload in
`static/js/sportsbook-production-fix-persist-reliability.js` and
`static/js/sportsbook-multislip.js`. Reverting it makes the client stop sending
a key; the backend then falls back to the 2-minute signature guard exactly as it
behaved before, with no schema or API change required. Also revert or skip
`tests/sportsbook-idempotency-guard-test.js` if you revert the wiring, since
that guard exists to stop a silent removal.

### 4. Cached-board selection fix — revert one commit

```
git revert 0e32c0a      # refresh TMR.currentGames when a board is restored from cache
```

One added line in `sportsbook/index.html`. Reverting reintroduces the bug where
switching back to an already-loaded sport could attach the previous sport's
game to the slip, so only revert it if it is proven to cause something worse.

### 5. Per-matchup alternate grouping + board clarity - revert one commit

```
git revert 4672cba
```

Touches `sportsbook/index.html` (the alt board renderer and a moneyline branch
in `selectAltBet`), the new `static/css/sportsbook-altgame.css`, and the v2
layer. Reverting restores the flat alternate grid; no data, feed, grading or
submission behaviour changes either way.

### 6. UFC total-rounds mapping — revert one commit

```
git revert 83df19c      # UFC Total Rounds map to mma_total_rounds (+ larger v2 chips)
```

This commit contains BOTH the market-mapping fix and the enlarged v2 odds
chips. If only the chip sizing needs to change, edit the `Pass 6/7/8` blocks at
the end of `static/css/sportsbook-v2.css` instead of reverting.

## Regression suite (must pass before any future sportsbook change)

Static, no network, run by `npm run verify:regression` (and its `--static-only` mode),
which `AGENTS.md` already requires before any sportsbook change is called complete:

- `tests/sportsbook-idempotency-guard-test.js` — fails if the submission
  identity wiring is edited away on either submit path.
- The existing sportsbook locks (visual, reliability, submit flow, stake mode,
  units normalisation, F5 layout, pitcher, header, protected baseline).

Live browser suites, all of which intercept `POST /api/picks` and therefore
**never record a pick**. They need a member JWT file path in
`TMR_TEST_JWT_FILE`; without it they print `SKIP` and exit 0.

| Command | Covers |
| --- | --- |
| `npm run verify:sportsbook-suite` | boards for every sport, odds vs board API, spread/ML/total selection, Risk/To Win/units maths, Lock, duplicate re-lock, refresh, back-nav, two concurrent users, console/network cleanliness, desktop/tablet/mobile |
| `npm run verify:sportsbook-idempotency-live` | key present, stable across double-click / 503 retry / re-press, new key on units, stake-mode, re-tap, refresh, back-nav |
| `npm run verify:sportsbook-switching` | selection, slip and payload stay attached to the visible game across every sport-switch order |
| `npm run verify:sportsbook-ufc-rounds` | UFC rounds Over/Under and fighter ML map to the right market, plus MLB spread/ML/total regression |
| `npm run verify:sportsbook-multipick` | add 1-4 selections, remove from the ticket and by re-clicking the line, per-card units, + stepper, apply-to-all, Risk/To Win, confirm modal, one POST per pick, contest mode stays single-pick, mobile drawer |
| `npm run verify:sportsbook-altgame` | each matchup is one card (header, primary markets, collapsed alternate spreads and totals), inline expansion, and that a primary moneyline records h2h while alternate spreads/totals record their own market with a line |
| `npm run verify:sportsbook-health` | production health probe used during rollout (JS errors, API errors, duplicate/malformed picks, odds loading) |

`node tests/sportsbook-v2/idempotency-api.cjs` proves the backend contract
(replay, 409 on a reused key with a different payload, new key = new wager) but
it **records real picks** and must not be run against production without
explicit approval.
