## Mechanism

GitHub Pages serves this site and cannot send an HTTP 301. The site's existing redirect
mechanism is the static stub: the old path keeps an `index.html` with a canonical to the
target, `<meta http-equiv="refresh" content="0;url=...">` and `location.replace`. The alias
stubs (/account/, /signin/ and the rest) and the forum builder's renamed slug stubs already
use it, and Google treats an instant meta refresh as a permanent redirect. Each old path below
now holds that stub, in the same format its family already uses (forum: the exact stub
`build_forum_threads.py` writes for a renamed thread; NFL: the alias stub format). A true HTTP
301 would need a Cloudflare redirect rule, which is host config outside the repo.

## Slug rules

- NFL: 49ers and Rams meet twice a season. A dateless pair slug would collide with the second
  meeting (at SoFi), so the week 1 game takes its one of a kind venue:
  `/nfl/49ers-vs-rams-melbourne/`. The existing dateless pages for this pair are
  `/handicapping/nfl/san-francisco-49ers-vs-los-angeles-rams-290802/` (different path) and
  `/nfl-game-of-the-week/week-1-49ers-rams-melbourne/` (different path), so nothing collides.
- Forum: `/forum/thread/<id>/` is kept. Slug = the title slug with the date removed
  (`scripts/dateless_slug.py` strip_dates: m-d-yyyy, yyyy-mm-dd, month plus day, bare years;
  a bare m-d is kept because in a betting title it is usually a spread). Where what remains
  is generic (`mlb-picks`), the slug is `mlb-picks-` plus the card's first play from the
  thread content, extended by the second play when the first was already used. The id keeps
  every URL unique even where two one play cards share a play (268 and 326).

## What changed

Frontend (`trustmyrecord`):
- The 49 pages moved with `git mv`; canonical, og:url and JSON-LD urls now name the new URL.
- Stubs written at all 50 old paths (the thread 60 stub from an earlier rename now points
  straight at the new URL, so it is not a chain).
- sitemap.xml: old locs replaced by new ones. Internal links updated in forum boards,
  /best-online-sportsbooks/, data/featured-matchups.json, /handicapping/nfl/,
  /nfl-game-of-the-week/ and its week 1 page, and the Bills Texans page.
- `data/forum-slug-overrides.json`: the frozen id to slug map. `build_forum_threads.py`
  applies it through `dateless_slug.public_slug()` everywhere it builds a thread URL, so the
  30 minute prerender keeps the new URLs and writes the old ones as stubs, before or after the
  backend migration runs. Existing URLs outside the map are never rewritten.
- Generators: `build_sport_matchup_pages.py` hook_slug and mint_slug and
  `sports_featured_rotation.py` build_slug strip dates and years, so no new matchup URL can
  carry one.

Backend (`trustmyrecord-backend`):
- `services/datelessSlug.js` plus `routes/forum.js`: new threads get a slug with dates
  removed ("7-17-2026 MLB Picks" becomes `mlb-picks`).
- `database/migration_forum_dateless_slugs_20260924.sql`: PREPARED, NOT RUN. Sets the stored
  slug of the 48 threads to the new value, guarded on the old slug.
