# SEO audit and fixes, 2026-09-24

Branch `cloud-audit-seo-20260924` (frontend, off origin/main 53b27d4d3e) and the same branch
name in trustmyrecord-backend (off origin/master). Nothing deployed, nothing merged, nothing
submitted to Search Console or IndexNow. No noindex added, no URL renamed or deleted.

## Method

1. Live, read only: `python scripts/seo_audit.py` against all 2063 live sitemap URLs
   (result: ALL SEO CHECKS PASSED: 200, no redirect, no noindex, self canonical, title and h1).
   Live robots.txt: `Allow: /` plus `Sitemap: https://trustmyrecord.com/sitemap.xml`. Repo
   sitemap.xml equals the live one (2063 locs, no diff).
2. The existing gates only look at URLs already IN the sitemap, so a new whole repo audit was
   written and committed: `scripts/seo_site_audit.py` (`npm run audit:seo-site`). It scans
   every tracked HTML page and reports canonical presence, host and exactness, JSON-LD parse
   validity, titles and descriptions (missing and duplicated), sitemap coverage, orphans
   (no static inbound link and not in the JS global nav), dates or years in URLs, and internal
   links that cost a redirect hop (alias stubs, directories without a trailing slash).
3. Every issue below was confirmed on the live HTML with curl before it was fixed.

## Fixes

### 1. 76 live NFL and NHL matchup pages missing from the sitemap
- Problem: 76 pages under /handicapping/nfl/ and /handicapping/nhl/ were live, 200, self
  canonical and index,follow but absent from sitemap.xml (six more had been patched in by hand
  on 2026-09-24 in a KEPT block).
- Root cause: `update_sitemap()` in `scripts/build_sport_matchup_pages.py` rebuilt its block
  from today's board only, so every page fell out the morning after its game.
- Fix: new `historical_pages()` lists every per game page on disk that is self canonical with
  no noindex and no refresh; `update_sitemap()` now emits them (weekly, 0.5, lastmod from the
  page's own build stamp) after the board rows, skipping anything listed in another block.
  Automatic on every four times daily bake, no manual step. The block was regenerated offline
  once in this branch: 2063 to 2139 locs. All 76 new URLs were fetched live: 76 of 76 return
  200, exact self canonical, no noindex.

### 2. NFL and NHL matchup pages with no inbound link
- Problem: 18 NFL and NHL research pages had no static link from anywhere once their game
  left the board.
- Root cause: the sport hub and sibling pages only link the live slate.
- Fix: `earlier_matchups()` in `build_sport_matchup_pages.py` and an "Earlier <sport> matchups"
  link section in `scripts/handicap_hub.py` (newest 120, labelled with teams and game date).
  The hub HTML is not rebaked here (needs the live board and engine key); the next scheduled
  sport hub bake after merge writes it.

### 3. Duplicate titles and descriptions on repeat meetings (NHL)
- Problem: Kraken at Flames (293247, Sep 20; 401891777, Oct 1) and Oilers at Canucks (293277,
  Sep 24; 401891829, Oct 1) had byte identical titles and descriptions.
- Root cause: the no hook fallback title in `scripts/handicap_page.py` carried teams only.
- Fix: the fallback title and description now carry the Eastern game date (title and
  description only, never the URL). The four existing pages were retitled the same way.

### 4. Duplicate titles on MLB doubleheaders
- Problem: five doubleheaders (Blue Jays at Orioles Sep 23, Cubs at Red Sox Sep 25, Orioles at
  Yankees Sep 25, Rays at Yankees Sep 22, Tigers at Guardians Sep 4) had identical titles on
  both games. Game numbers verified against statsapi.mlb.com.
- Root cause: `scripts/build_mlb_matchup_pages.py` title builder ignored `game_number`, and the
  hook store keys on teams plus date, so both games also shared the hook.
- Fix: " Game N" added to both title forms and ", game N of a doubleheader" to the description
  when `doubleheader` is set. The ten existing pages were retitled to what the builder now emits.

### 5. Matchup of the Day featured pages: duplicate titles and descriptions, missing schema, orphaned
- Problem: 13 pages written by `scripts/sports_featured_rotation.py` failed
  `tests/matchup-seo-contract-test.js` on main (54 failures): no og:image, no Article or
  BreadcrumbList JSON-LD, not linked from /matchup-of-the-day/, and angle headlines like "The
  price on this game is a pick" gave four duplicate descriptions and two duplicate titles.
- Root cause: the page template shipped a lone SportsEvent node and the angle sentence as the
  meta description; the pages were reachable only through the per sport door while current.
- Fix: `featured_ld()` emits Article (datePublished, dateModified) + BreadcrumbList +
  SportsEvent; og:image added; description leads with the matchup; the title leads with the
  matchup when the headline names neither side; new `_sync_hub_links()` keeps a
  `<!--MK:featuredAngles-->` list on the hub (outside the motd* markers the daily bake
  rewrites). The 14 existing pages and the hub were updated in place. Contract test now passes.

### 6. Forum threads dropping off their boards
- Problem: 54 live thread pages had no inbound link (the MLB board listed 72 of 116 threads,
  strategy listed 0 of 3). They stay in the sitemap.
- Root cause: `scripts/build_forum_threads.py` built board lists from `built`, the threads
  whose per thread fetch succeeded that run; a transient fetch failure kept the page but
  removed it from its board.
- Fix: boards now list every enumerated thread whose page is on disk, using fresh detail when
  available and the enumeration row otherwise. Takes effect on the next prerender refresh.

### 7. Missing meta descriptions and canonicals
- 11 pages had no meta description (login, register, reset password, verify email, friends,
  pending picks, wallet, wallet referrals, wallet rewards, activation, profile widget); 5 had
  no canonical (activation, arena challenge view, arena league view, profile sport,
  profile-widget.html). Added, self referencing, absolute https, line endings preserved.

### 8. Internal links through alias redirect stubs
- 36 links on 23 static pages pointed at meta refresh stubs (/leaderboard/, /make-picks/,
  /signin/, /signup/, /account/, /polls-trivia/), plus one in
  `static/js/tmr-sport-leaderboard.js`. Repointed at the canonical targets (/leaderboards/,
  /sportsbook/, /login/, /register/, /profile/, /polls/).

### 9. Backend: API host robots.txt
- `routes/nflPublic.js` robots.txt pointed crawlers of trustmyrecord-api.onrender.com at that
  host's own sitemap, which can only list a trustmyrecord.com URL (not accepted cross host).
  It now references https://trustmyrecord.com/sitemap.xml. `tests/nfl-public-test.js`
  assertions still hold.
