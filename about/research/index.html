Methodology

TrustMyRecord Research

“TrustMyRecord Research” is the byline on our TMR Game Files. It is not a person, and we are not going to invent one. It is the name for the research function of TrustMyRecord: the tools that produce the numbers, the process that checks them, and the human who signs off before anything publishes.

Why an organisational byline

A Game File is assembled from several TMR systems and then written and reviewed by a person. Attributing that to a made-up staff writer with a stock headshot would be the single most dishonest thing on the page, and it is a common enough trick in this industry that we would rather say plainly what the byline means. Where a named individual is genuinely responsible for a piece of analysis, that person is named on that article.

What we use

TMR’s own tools

  • BetLegend Pro — our historical database. Used to ask whether a situational angle has actually happened before, and how often, rather than assuming it.
  • Trend Spotter — our situational trend engine. Trends are reported with the number of games behind them.
  • TMR MLB Simulator — used to simulate the specific matchup. Where we quote a simulation, we say how many runs it was based on.
  • The TMR Handicapping Hub and our verified record system, where the behaviour of real tracked bettors is relevant to the game.

External data

  • The official MLB Stats API, for schedules, rosters, transactions, player biographical data and handedness.
  • Licensed odds and market data from the providers that feed TMR’s board, for prices, spreads and totals.

External data is identified as external. TMR analysis is identified as TMR analysis. Those are two different claims and a reader is entitled to know which one they are reading.

How every number is sourced

Behind each Game File is a provenance record. For every quantitative claim that reaches the page we store the metric, its value, the sample it came from, the source, the tool endpoint that produced it, the calculation if it was derived, and the time it was retrieved.

This is enforced rather than encouraged. Our publishing system refuses to publish an article containing a number that has no matching provenance record; the article stays a draft until the record exists or the number comes out. We built it that way because a research page’s only real asset is that its numbers are true.

Every claim is stored as one of three kinds:

Fact
A measured value from a named source. Example: a starter’s season ERA from the MLB Stats API.
Derived
Something TMR calculated. We keep the inputs and the calculation, so the figure can be reconstructed rather than taken on faith.
Analysis
Our judgement. Which evidence we think matters, and why. This is the part that is genuinely opinion, and it is labelled so it cannot be mistaken for a measurement.

Sample size

Most misleading sports statistics are not false; they are true and tiny. “He is 3-for-5 lifetime against this pitcher” and “he has a .380 on-base percentage against left-handed pitching over 500 plate appearances” are both accurate, and only one of them is evidence.

Game Files therefore print the sample next to the number, and our editorial language distinguishes findings that are strong, supportive, interesting, small-sample or contradictory. A trend with six games behind it is described as a trend with six games behind it.

How automation is used

We are explicit about this because it is where most sites are not.

Data collection is automated: schedules, rosters, transactions, historical queries, trend queries and simulation runs are pulled from the systems above by software, and the provenance record is written at the same time.

Selection, interpretation and publication are not automated. A person chooses which game becomes the Game File, reviews the assembled research, writes or approves the editorial sections, and presses publish. No Game File publishes without that review.

As we automate more of the assembly work, this page will be updated to say exactly what changed. We will not describe a capability here before it exists.

Publication and updates

Every Game File is a permanent publication with its own permanent URL. We do not recycle a URL for a different game, and we do not delete an analysis because the game finished. Yesterday’s Game File stays exactly where it was published.

Each article shows when it was published and, if applicable, when it was last materially updated. “Materially” means something that changes the analysis — a confirmed lineup, a starting pitcher change, a significant injury or weather development, a corrected statistic, new research or a fresh simulation run. A live odds widget refreshing itself is not a modification and does not touch the update timestamp.

Where we later add a postgame section, the original pregame analysis is left intact and clearly labelled as pregame. We are not going to quietly improve our own predictions after the result is known.

Corrections

If a number on a Game File is wrong, we want to know and we will fix it and say that we did. Contact us with the article and the figure in question.

What this is not

A Game File is research and analysis. It is not betting advice, and it is not a guarantee of anything. TrustMyRecord exists because we think the honest version of this industry is one where records are public and checkable — you can see every tracked bettor’s actual results on our leaderboards, wins and losses alike.
